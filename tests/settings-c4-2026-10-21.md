Image publishing: this push **did** trigger the image workflows (`settings-images.yml`,
`config-server-image.yml`), and the same two workflows were also dispatched explicitly
(`gh workflow run --ref main`), so two builds raced on the same tags per image. Harmless for
settings-tui (both builds are the same commit; tag points at one of them), but worth avoiding:
use **either** the push-triggered run **or** one dispatch, never both. Note the tag shapes differ —
`settings-images.yml` publishes full-SHA tags (`sha-<40>`), `config-server-image.yml` publishes a
7-char short-SHA tag (`sha-5ee5ec1`, like the previous `sha-901d8a7` pin).

## Caveats and follow-ups

- The TUI's `created N/max` count is advisory display data: it counts the owner's listed
  templates' boxes, while the config server's cap check (list-based, authoritative) also counts
  boxes created from templates no longer published to this owner. Documented in
  `settings-tui/README.md`.
- The differential renderer repaints changed cells only; tests asserting the cap line must
  tolerate the count arriving separately from the painted `created` label (applied in the Docker
  smoke and PTY tests).
- Open issues unchanged: #10 (two real owners), #12 (PVC), #13 (metrics/top).
